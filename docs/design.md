# Sift — 首版设计草案

状态：项目名称为 Sift，采用 Node.js + TypeScript + Effect。核心行为已确认；下文标为“待定”的接口细节和运行参数尚未确定。当前仓库仅包含设计与实验，MCP 功能尚未实现。

## 目标

主模型提供命令和查询目的。工具拥有执行、原文保存、分块、相关性判断和结果返回的完整链路，避免原始大输出先进入主模型上下文。目标是减少整个任务的上下文和成本，同时保持任务正确率，而非单纯追求压缩率。

## 已确认的范围

- Node.js + TypeScript + Effect；本地 stdio MCP。
- 首版支持有限时长、非交互、文本输出命令；不支持常驻服务或交互终端。
- 运行权限继承 MCP 进程。查询用途不是权限保证；不添加模型语义准入器，不把本工具宣传为沙箱。
- 主模型提供查询目的、命令、工作目录；是否适合调用由主模型判断。
- `execute` 返回通过统一阈值的原文；`read_result` 支持原文范围回读。
- 第一版使用 Jev；判断服务可替换。使用单个相关性判断，不另设独立 confidence 门槛。
- 阈值由工具配置，不开放每次调用覆盖。数值通过标注样本评估确定。
- 低于阈值的区段不进入主模型上下文。原文保留，支持有期限的回读。
- 判断失败、未处理、低于阈值分别记录。部分结果必须声明不完整及未处理范围。

## 处理流程和模块职责

1. MCP 参数经过运行时校验，创建 result ID 和执行作用域。
2. Executor 启动命令，独立捕获 stdout/stderr，流式写入 ArtifactStore。
3. 记录退出码、超时、取消、输出截断等执行事实。不能把命令成功等同于查询有答案。
4. ChunkStrategy 输出目标区段及前后辅助上下文。策略只组织材料，不提前筛除原文。
5. JudgeProvider 判断目标区段是否有助于回答目的，包括反证、否定结果和会改变结论的限制信息。
6. 有界调度器执行判断；结果通过严格 Schema 校验。筛选规则由工具拥有。
7. Renderer 按原始位置返回通过阈值的原文，合并相邻目标区段；辅助上下文不自动返回。
8. 结果、判断状态、源位置和配置版本保存在 Store，支持补读与排查。

stdout/stderr 分别保持自己的字节顺序；不声称可以从两个独立管道恢复唯一全局时序。

## 公开工具契约（草案）

`execute` 输入：command、cwd、purpose。命令表示方式（shell 字符串或 executable/args）及首批操作系统支持范围待定；在实现 Executor 前确定，避免隐式 shell 差异。

输出包括 result_id、执行状态、判断完整性、来源区段、通过的原文、回读提示。运行参数由服务器配置，调用者不能提高阈值、输出上限或资源预算。

`read_result` 输入：result_id、stdout/stderr、范围。常规行号回读需有严格单次字节上限；超长单行使用字节范围或续读 cursor，不能为了读取一行加载整个超大结果。精确公开字段在接口规格中固定。

任何自动输出省略都可区分：低于阈值、判断未完成、原始捕获截断、返回预算截断。空筛选结果仅表示没有区段通过门槛，不证明原始资料不存在答案。

## 分块契约

- 原始数据按字节保存，证据通过源位置提取，不让判断器重写。
- 默认按行边界构造窗口，达到字节硬上限必须切分，允许拆超长单行。
- 每个捕获到的字节属于一个目标区段；目标区段不重叠、不漏尾部，辅助上下文允许重叠。
- 为每个区段记录流、字节范围、行号及必要的行内位置。
- UTF-8 跨读取缓冲区及跨分块边界必须正确处理；无效文本的处理策略需要明确，不能默默替换后称为原文。
- 分块策略可按命令及输出格式选择；未知格式使用通用窗口策略。
- 相邻上下文能缓解局部边界问题，不能保证跨远距离依赖的语义完整性。

## Effect 使用边界

- 在 MCP 入口统一进入受管 Effect runtime；错误、取消和资源生命周期在内部连贯传递。
- 命令、文件、判断请求有 owner 和关闭逻辑；不产生无 owner 后台任务。
- 纯分块算法、区段合并和阈值比较使用普通 TypeScript 函数。
- Provider 预期错误与程序缺陷分别处理；错误响应不能伪装为低相关性。
- 不自动重试命令。判断服务重试策略待定；若启用需受总 deadline 和预算约束。
- Effect interruption 不等于任意 SDK/操作系统操作已取消；对接处显式连接 AbortSignal、进程终止和退出等待。

## 生命周期和资源限制

运行配置需要覆盖命令 deadline、判断 deadline、捕获字节数、目标块和上下文大小、请求并发、总判断请求/输入预算、返回字节数、原文保存期限及总存储上限。

具体默认数值待首版样本评估；基准中的 8 KiB 区段、2 KiB 前后文和每命令并发 4 只是实验参数，不能当作质量已验证的产品默认值。

输出超限时必须停止继续无界捕获并声明截断；是否立即终止命令需写入执行契约。清理任务归 Store 作用域所有；回读中的 Artifact 不与到期清理竞态。已过期或已被清理结果明确报错。

原文在本地保存；相关区段和上下文会发送给所配置的判断服务，这一点必须写入 README 和配置说明。任何鉴权信息只来自服务器配置，不进入工具结果或诊断日志。结果 ID 不可用于任意文件路径读取。

## 首版验证标准

确定性 contract 测试：
- 空输出、缺少末尾换行、CRLF、中文/emoji、无效 UTF-8、超长行和随机读取边界。
- 目标区段覆盖原文、源位置可重建、并发完成乱序后仍按原顺序返回。
- stdout/stderr 同时大量输出，不死锁；命令退出失败不被改写为成功。
- 判断服务超时、非法概率、缺失响应和部分失败分别反映到结果。
- 取消后文件句柄、直接子进程及需支持的进程树得到回收；原文清理与补读不竞态。
- 所有资源上限实际生效；超大单行的回读和返回都不能绕过字节上限。
- 真正通过 stdio MCP 客户端调用两个工具，确认 stdout 不混入诊断日志。

质量评估：真实查询目的+原始输出+人工标注关键证据；覆盖反证、零测试、表头/数据分离、跨块堆栈和远距离说明。比较块大小、边界偏移及阈值变化后的证据召回、误保留、最终任务正确率、补读次数和总费用。

性能评估：本地处理耗时、峰值内存、事件循环延迟、取消响应、真实判断服务等待、请求数量与总输入量。不得将压缩后的单次输出 token 当作整个任务节省。

## 已有性能证据

benchmarks/local/RESULTS.md 和 benchmarks/local/comparison-results.json 保存五轮交错运行结果。100 MiB 多行输出：Effect 约 668 ms / 217 MiB，Rust 约 582 ms / 3 MiB。仅处理进程，不含远程判断和完整 MCP SDK。数据支持首版优先开发成本，但不支持声称 Node 与 Rust 的内存相近。

100 MiB 以约 8 KiB 分块会产生约 1.27 万个候选，网络请求和判断成本需要单独控制。Rust 对照还发现旧原型硬切块的跨缓冲区越界问题；生产实现不能直接复制原型，需要先完成分块 contract 测试。

## 实施顺序

1. 补齐命令表示、首批平台、关键默认参数和持久化契约。
2. 实现纯分块与存储、fake JudgeProvider，验证确定性行为。
3. 接入受管命令执行和真实 stdio MCP，验证取消和资源边界。
4. 按最新官方 SDK/API 文档接入 Jev；使用小型可公开 fixture 做集成验证。
5. 标注实际样本并校准阈值，跑完整任务质量和成本评估，再接入用户项目试用。

首版不实现远程执行、本地推理、动态加载第三方插件、完整命令解析器集合或 Node/Rust 混合架构。
