# Running Sift

Sift is an experimental local stdio MCP server for Node.js 24+ on macOS/Linux. The current release supports explicit executable/argument arrays, not interactive terminals. Shell expressions require an explicit shell invocation. Windows is not supported yet.

## Build and connect

```sh
npm ci
npm run check
```

Configure your MCP client to launch `node /absolute/path/to/sift/dist/cli.js`. Provide the API key via the client's environment/secret mechanism, not command arguments:

```json
{
  "mcpServers": {
    "sift": {
      "command": "node",
      "args": ["/absolute/path/to/sift/dist/cli.js"],
      "env": {
        "TYPESAFE_API_KEY": "<your key>",
        "SIFT_THRESHOLD": "0.8"
      }
    }
  }
}
```

**0.8 is an illustrative trial value, not a calibrated recommendation.** There is deliberately no default threshold. Benchmark results establish local processing performance, not judgment quality. The server does not accept a per-call threshold.

Sift executes with its host user's permissions. It is not a sandbox and has no semantic command admission filter. Non-interactive commands can still modify files or invoke external services. The TypeSafe API key itself is removed from the spawned command environment; other environment variables are inherited. Original output is retained locally and judgment windows are sent to TypeSafe. The SDK logger is disabled; stdout is reserved for MCP.

## Tools

`execute`:

```json
{
  "executable": "rg",
  "args": ["--line-number", "retry", "src"],
  "cwd": "/absolute/path/to/project",
  "purpose": "Find evidence of retry limits, including paths with no retries."
}
```

Use `{"executable":"/bin/sh","args":["-c","your pipeline"],...}` when a shell is needed. Sift never retries commands. `execution.status` distinguishes ordinary exit (including nonzero exit codes), timeout, cancellation, output limit and spawn failure. Timeouts, cancellation and output overflow hard-kill the owned POSIX process group; the group is also cleaned up when its leader exits. Descendants that deliberately escape the group are outside this mechanism; it is not containment.

`judgment.complete` describes only captured-output judgment coverage, not command success or semantic correctness. `execution.truncated` indicates capture loss; `output_truncated` indicates that retained evidence exceeds the response budget. Failed and unprocessed ranges are distinct from filtered spans. Provider configuration, authentication/permission, and rate-limit failures have separate issue reasons; provider response bodies are not returned. Judgment metadata identifies the provider and requested model. A small response can abbreviate issue ranges and marks `issues_truncated`; full decisions remain in the local manifest. Below-threshold content is never automatically returned.

`read_result`:

```json
{
  "result_id": "<ID from execute>",
  "stream": "stdout",
  "offset": 0,
  "limit": 4096
}
```

Ranges are zero-based byte offsets with an exclusive end. Follow `next_offset` until `eof`. UTF-8 reads end at a code-point boundary; an offset inside a code point is rejected. Invalid UTF-8 streams are not sent to the judge and are returned as explicit base64. Failed artifacts use base64 for recovery because complete text validation may not have finished. Raw bytes are not normalized: CRLF, BOM and trailing-newline differences survive.

Capture streams have independent ordering; Sift does not invent a combined stdout/stderr chronology. Internal chunk positions record one-based line and byte-column coordinates. Original evidence is copied from stored bytes, not generated by the model.

## Server configuration

`SIFT_CONFIG` optionally points to a JSON object using the fields below. `SIFT_STATE_DIR` and `SIFT_THRESHOLD` override their corresponding JSON fields. Unknown fields, invalid values, and oversized command inputs (>64 KiB serialized) are rejected.

| Field                |  Experimental default | Meaning                                                               |
| -------------------- | --------------------: | --------------------------------------------------------------------- |
| `threshold`          |              Required | Inclusive probability cutoff in [0,1]                                 |
| `model`              |          `jev-latest` | Requested TypeSafe model                                              |
| `stateDir`           | `~/.local/share/sift` | Absolute artifact directory                                           |
| `commandTimeoutMs`   |                30,000 | Command deadline                                                      |
| `judgeTimeoutMs`     |                10,000 | Per-judgment deadline                                                 |
| `judgmentDeadlineMs` |                60,000 | Whole judgment phase deadline                                         |
| `outputBytes`        |                 8 MiB | Combined captured stdout/stderr limit                                 |
| `chunkBytes`         |                 8 KiB | Target span upper bound                                               |
| `contextBytes`       |                 2 KiB | Context allowance on each side, aligned inward to UTF-8               |
| `concurrency`        |                     4 | Concurrent judgments, one execute operation at a time                 |
| `maxJudgments`       |                   128 | Maximum provider calls per execution                                  |
| `judgmentBytes`      |                 2 MiB | Reserved serialized provider input bytes                              |
| `responseBytes`      |                24 KiB | Serialized execute-result JSON budget, excluding MCP framing          |
| `readBytes`          |                24 KiB | Maximum original bytes per read; JSON/base64 encoding can expand this |
| `retentionMs`        |              24 hours | Result accessibility lifetime from creation                           |
| `storageBytes`       |               256 MiB | Artifact quota with capture and metadata reservation                  |
| `maxResults`         |                   100 | Maximum retained result directories                                   |

Timeouts are capped at one hour. Capture is capped at 64 MiB. Chunk size is 256–65,536 bytes and outputBytes/chunkBytes must not exceed 4,096. Context is at most 65,536 bytes per side. Concurrency is at most 16, calls at most 4,096, result count at most 1,000. Response budget is 2 KiB–1 MiB; read limit is 4 bytes–1 MiB. Storage must reserve outputBytes plus 8 MiB for metadata/atomic writes. These bounds control resources, not semantic completeness.

Requests are admitted in source order (stdout, then stderr) until budgets prevent admission; all other spans remain explicitly unprocessed. No automatic retries are enabled in the first provider. Clients should allow enough time for both command and judgment deadlines, or send cancellation.

## Storage lifecycle

Directories are private (0700) and files are 0600. One server owns a state directory using `.lock`. Results persist across clean restarts. Expired results become unreadable immediately; physical deletion is lazy, on startup and before the next execution. Active read/execution leases prevent deletion races. Unexpired results are not silently evicted to make room.

Graceful EOF/SIGINT/SIGTERM waits for active request cleanup and releases the lock. A hard process crash can leave a stale lock or a `running` artifact; do not remove the lock until its recorded PID is no longer an owner. In this first version, interrupted crash artifacts require operator cleanup while Sift is stopped. No automatic crash-recovery command re-execution occurs.

Provider adapters must honor AbortSignal and release resources before rejecting cancellation. Chunk strategies must cover every captured source byte without overlap or omission and respect chunkBytes. Both seams are programmatic interfaces, not dynamically loaded plugins.

## Validation status

Local contract tests use a fake judgment provider or the real TypeSafe SDK with a mock HTTP transport. They do not establish Jev's relevance quality. `npm run smoke:live` is an explicit opt-in, billable SDK check using public synthetic text only; it does not send repository files. Live SDK and production stdio MCP checks have also run successfully; see the [recorded pilot](../eval/README.md). Full task-quality evaluation and threshold calibration remain follow-up work. `jev-latest` is a moving alias verified against the available-model API, not a pinned release. An unavailable configured model fails explicitly; Sift does not silently choose another model.
